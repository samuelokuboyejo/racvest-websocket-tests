How these pages work

Every page connects to the realtime service (for example http://localhost:8090) over STOMP, with the same access token the app uses after logging in to Racvest. Racvest itself is only used to create deliveries, bids and so on (Postman or the app). The server URL, tokens and IDs you type are remembered in this browser and shared between pages, so you only paste them once. Open each page in its own tab to play both sides.

Which server URL? On the hosted site, use the realtime service's https address for the environment you are testing. http://localhost:8090 also works from the hosted site in Chrome, which may first ask to allow access to devices on your local network. Saved tokens stay in your browser only and are never sent anywhere except the server you connect to.

Test the whole delivery flow

The quickest way is Delivery flow, which shows both sides at once. To test one side on its own, use the single pages:

  1. Open All courier events (or New delivery requests) with a courier token and leave the heartbeat on. The courier is now available.
  2. Open Delivery request events with the sender token and connect.
  3. Create a delivery request as the sender (Postman or the app), paste its ID into the sender page and press Watch.
  4. The courier page should show DELIVERY_LIVE within a few seconds. Place a bid as the courier: the sender page shows BID_PLACED.
  5. Accept the bid as the sender: the courier gets BID_ACCEPTED and a chat opens between them. Try it on the Chat page, which shows both sides at once.
  6. Open Publish location as the courier, choose On a delivery, enter the delivery ID, pick a destination and press Drive, then Start publishing.
  7. Open Track delivery as the sender with the same delivery ID: the courier moves on the map, and the status timeline moves as the courier updates the delivery status.

If nothing arrives

  1. The courier must be available: connected, active role COURIER, and a heartbeat in the last 30 seconds.
  2. The IDs you type must belong to the token. Realtime only delivers a user's topics to that user.
  3. Racvest must have racvest.realtime.enabled=true, and both services must point at each other.
  4. Open the browser console (⌥⌘J) for connection errors, and check the realtime log for presence rejected warnings.
